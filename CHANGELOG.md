# Changelog

## 0.8.2 (2026-11-02)

- **Clearer code for the directory check.** Two local names that repeated the names of top-level functions (`choices` in the keep-warm offer, `choice` in closing it) are renamed, and four hook error handlers no longer name their first parameter `$`, so the directory's check can tell which function a call means. No change in behaviour. `scripts/check-plain-dollar.mjs` now checks this and is part of the contributor checks.
- **Less that looks like credential handling.** Comments, test text and two setting descriptions no longer use words such as "API key", "login" or "tokens" where they were not needed. rightsize still reads no credential; the only environment value it reads is `HOME`.
- **A settings reset you can paste.** When Claude Code will not write a setting from the desktop app, the message now gives one command with the values after `<<<` instead of piping them in with `echo`. The README and `docs/SETTINGS.md` show the same form.
- **Plugin listing:** the support, documentation, privacy-policy and terms links are no longer listed in `plugin.json` (the directory reported them as unrecognized fields); the README and `docs/PRIVACY.md` still carry that information.
- **Tests split into smaller files.** The big `register.test.ts` is now ten `register.*.test.ts` files plus a helper file `hooks/testkit.ts`, each under 100 KB, so the directory can read every file. The same 1,560 tests run.

## 0.8.0 (2026-11-01)

- **Hand-downs start only from Opus or Fable.** A helper on a cheaper model is used only when your session runs on Opus or Fable. From Sonnet, the brief and the check cost more than Haiku saves, so the work stays in your chat. Hand-ups and moving Claude's own subagents are unchanged.
- **Three switches: Routing, Hand-offs, Cache.** Three new rows in `/config`, third to fifth after Profile and Mode, each on or off (default on), turn one part of rightsize off and leave the rest running. Routing covers effort changes on your main chat, the review switch to Opus and the mid-turn raises. Hand-offs covers helper subagents and moving Claude's own subagents to a cheaper model; with Routing on, an effort change takes the place of a hand-off. Cache covers keep warm, the cache offer, the handoff or compaction before the cache goes cold and the idle warning; turning it off stops a keep-warm run at once. With Routing and Hand-offs both off, rightsize rates no prompt, so nothing is spent on rating, and the cache features still work. A row that belongs to a feature that is off is not used and keeps its value. `/rightsize status` has a `Features:` line, and the log says when a plan was dropped because its feature is off.
- **The profile answers the four cases; nothing holds your prompt.** A rule row left at not set now means your profile decides: Balanced lowers, raises, switches reviews and hands off without asking, Quality asks before lowering or using a cheaper model, Economy stays on your model rather than a stronger one. The first time each case comes up in a session the band says so (`Your Balanced profile decided (Cheaper model); ⋯ changes it.`), and the other rules are in the band's ⋯ menu. The four questions are no longer asked as dialogs; `/rightsize settings` still asks them. The Remember question follows only a rule you set yourself.
- **Mode: act or watch only.** A new row, second in `/config`. Watch only rates and plans every prompt and applies nothing: the band says what rightsize would have done (`Watching: would send this to a Sonnet subagent at medium effort. ~26% of Opus usage. Mode in /config turns it on.`), and `/rightsize report` has a Watch only line with how many prompts would have changed and what that was estimated to save. Use it for a week before turning rightsize on.
- **A starting tip on day one.** On the first session on an Opus start, before the log can say anything (under 50 rated prompts), the band says once that most work runs as well on Sonnet 5.5 at medium for well under half the usage, that reviews still run on Opus and work Sonnet would struggle with goes to a stronger helper, with a `Switch: /model sonnet` button that puts the command in the prompt box, and Not now. The weekly log-based suggestion is unchanged. rightsize never changes the model itself.
- **Keep warm is a status, not an offer.** While Before the cache goes cold is not set, the profile decides: Quality keeps warm 8 hours, Balanced until your usual start time (new row value `keep warm until my usual start`: the time you usually send your first prompt, at most 8 hours), Economy lets it go cold. The band shows `Warm until 9:00 · ~0.3% so far` with Stop keeping warm, and Don't keep warm again in ⋯. The cap is unchanged: never more than coming back cold. The `ask` value, with its offer 5 minutes after the turn, is still there for anyone who sets it; no profile uses it.
- **Keep-warm wording, and a step-up on the 5-step rule is not a miss.** The keep-warm line drops "Keeping" and shows its zero before the first request: `Warm until 22:05 · $0.00 so far` on the API, `Warm until 22:05 · ~0% used so far` on a subscription (it used to say `nothing used yet`). A turn that stepped back up only because it passed 5 steps is no longer counted as a miss in the rater's scoring; one that stepped up after a tool error still is. The run log records which (`steppedUpBy`).
- **The cache offer counts down.** Its line says how many minutes are left and the clock time it goes cold (`Goes cold in 42 min (14:55) · coming back after costs ~2%`), and the band redraws it once a minute, from the timer it already has. It never says 0 min while the cache is warm.
- **The idle warning never holds the prompt.** When a prompt is sent after the cache expired and rewriting the conversation costs over the bar (now over $0.50 by default), the band notes the cost beside what rightsize did with the prompt, and what `/compact` first would have cost. The Idle dialog is gone.
- **Share is a row, not a question.** rightsize no longer asks after 20, 50 and 100 rated prompts. Share anonymous feedback in `/config`, `/rightsize status` and the report footer say whether it is on. The documented payload now lists everything sent: the plugin version, billing kind, conversation size, turn and rating times were sent before and not listed.
- **👍 and 👎 moved into the band's ⋯ menu** (`Mark this 👍 (right call)`, `Mark this 👎 (wrong call)`). They are kept on this machine and, when Share is on, sent as a number: the band no longer says nothing is sent anywhere.
- **Tests and corrections count as outcomes.** A test run that fails at the end of a turn (in the main chat or its helper) is a miss for a lowering or a hand-down; a next prompt the rater marks as correcting the reply (`corrects` in the rating) is a miss for the cheaper route before it, logged as a `corrected` line. The run log carries `tests` (passed or failed) per turn.
- **The review switch is for the review.** A follow-up in a review task that the rater types as something else (a lookup, a fix) is planned as that, not switched to Opus. Economy caps a switched review at high effort; Quality and Balanced at Highest effort.
- **An effort switch is priced as free once measured.** After 20 measured switches that missed the cache at most 5% of the time, a switch costs nothing in the estimate (Anthropic's docs say effort changes keep the cache on the current models), so lowering can pay on a big conversation too.
- **The rater is told that a bulk-edit, extract or summarize request with a clear rule fits Haiku at medium.**
- **A stuck helper whose dialog gets no answer goes on at its effort**, as it does on the band, instead of going back to the main chat.
- **The band's pacing note names the bars it moved** (`hand-off bar 70% → 85%`).
- Docs: the root README is a short landing page; the full rules, settings, what it touches, privacy and the measurement method are under `docs/`. Corrections from an audit of the README against the code: research priors count as 10 tasks; from Fable a review may go to an Opus subagent; `send` in the approval steps matches MCP send tools; the Workflow question is asked per Workflow call until answered; the report has a Time section.
- **Questions hold up your work for 30 seconds at most, and most not at all.** A question whose answer changes the prompt you just sent (the four rule questions the first time, and Effort, Stronger and Subagent when a rule is ask) is a dialog that waits 30 seconds, then takes the choice that changes nothing; **Question wait** in `/config` sets 30 seconds, 1 minute or 2 minutes. Every other question is now a row on the band in the terminal and the desktop app, and the work does not wait for it: Remember choices, Reports and Share show when the turn ends and stay until your next prompt; Stuck, for the main chat or a helper, shows during the turn (a Raise applies from its next request) and goes when it ends; Workflow shows as the workflow starts, paused, and stays until your next prompt. Press a number key to answer, or × to dismiss. A stuck helper no longer goes back to the main chat when nobody answers: it goes on at its effort. With Band set to Never, or on other surfaces, these are timed dialogs as before. Idle is unchanged: it is a dialog and holds the prompt until you answer.
- **The band is easier to read.** Each row is one topic with a dim label: Prompt, Cache, or the question's name. With two rows or more, ⋯ and × sit once on a `rightsize` header line, and × closes every row (a question closed this way keeps its no-answer default). The band shows one unit of cost per line: a hand-off's result on a subscription is `Sent to Sonnet. ~28% of Opus usage.`, with the dollars in ⋯; the Cache row reads `Goes cold in 42 min (14:55) · coming back after costs ~2%`, and its button `Keep warm to 16:00 (~0.1%)`. What happens with no answer is a dim line under a question, not part of it. The Remember question names your rules ("Keep your rules (Lowering: lower automatically) in every session?") and its answers are Every session and This session. The band shows at most three rows: a question that can wait does, while the Prompt and Cache rows both show, and it is not counted as unanswered until it has shown.
- **Share is asked up to three times.** Left unanswered or closed, the Share question comes back after 50 and after 100 rated prompts, then never again. A no is final.
- **Long runs are priced from a learned step exponent.** A run's cost grows more slowly than its step count, because later steps reuse the same cache. rightsize learns an exponent `g` (between -0.4 and 0) from your own runs and prices work for `steps ** (1 + g)` steps; a hand-off's own steps take 0.8 of it. Each run is scored with and without `g`. `g` is used for routing only after 50 scored runs, when it cuts the median estimate error by at least 10% and has stayed steady over the last refits; it stops being used if that gain falls under 5%. When it starts or stops, the calibration ratios are rescaled and the change is logged. Until then, the run log records the plan it would have made beside the real one. `/rightsize report` has a Step estimates line: learning, with how many of the 50 runs are scored, or applied since a date.
- **`/rightsize report` measures whole tasks.** A new Whole tasks section compares what each finished task cost with what rightsize estimated for it. A task is one goal, from its first prompt until the rater says a prompt starts a new goal; it is finished once a later task began in the session, or nothing was logged for it for a day. What it cost counts the main chat's turns (with their helpers and subagents, once), retries and stopped turns, the rating calls, the rater's checks and the keep-warm requests for the task. What was estimated is the sum of the estimates made as each prompt was rated, for the route chosen. The section gives the median of cost over estimate, the share of tasks that cost more than 1.5 times their estimate and where the extra of those came from (retries and rework, helpers, keep warm, other), what the tasks saved over staying on your own model, and the median by task type for the five types with the most tasks. It shows from 5 finished tasks; before that, one line says how many more it needs. On a subscription the dollar figure is labelled API-equivalent. Keep-warm requests and the rater's check lines now carry their task's id.
- **Keep warm is credited for the cold restarts it prevents.** When you send a prompt while a keep-warm run is going, or within a cache life of its last request, and after the time the cache would have gone cold without it, rightsize checks the prompt's first request: if it read at least about 80% of the conversation from the cache, one `warmSaved` line records what coming back cold would have cost (the conversation written again, less a read). If the cache missed, the log says so and nothing is saved. A run you never came back to stays pure cost. `/rightsize report` has a Keep warm line (`Keep warm: 4 runs · saved ~$3.20 on 3 returns · cost ~$0.90 · net ~$2.30 saved`, API-equivalent on a subscription), and Total saved and the band's session total include the saving. `warmSaved` lines are never shared.
- **New `/config` row, Before the cache goes cold.** When a session under 200K tokens ends a turn and a cold return would cost $0.50 or more (API-equivalent dollars on a subscription too), rightsize can act before the cache expires: `ask` (the Balanced and Economy default) offers priced choices in the band (keep warm 2 h, 8 h or until your usual start time, save a Groundwork handoff or compact, let it go cold, turn this off); `keep warm 2 h` and `keep warm 8 h` send one small request before each expiry and stop when you send a prompt, press Stop, a request fails, the end time comes, or keeping warm would cost more than coming back cold; `save a handoff` sends `wrap up` once for Groundwork (compacts without it); `compact` compacts once; `off` does nothing. Quality keeps warm for 8 hours; Balanced and Economy ask, unless you set the row. Each ping is a `warm` line in the run log and counts as rightsize's own cost in the report. The idle question counts the time since the last ping. Nothing runs during a turn.
- **Bare `/rightsize` opens a settings pane.** It lists every row of `/config` with its value, Profile first and the Advanced rows under a heading; a row you set is marked yours, the rest default. A pick takes effect at once, as a change in `/config` does. Where no pane can be drawn, or on the mobile app, it asks instead: pick a setting, pick its value, back to the list until Done. The old summary is `/rightsize status`.
- **The band names its confidence, and waits for the session total.** "How sure" is now `Confidence: high.` (or medium, low) on the band, and the counts behind it are in the ⋯ menu. The band's session total shows from the session's 3rd rated prompt; `/rightsize report` still counts from the first.
- **The cache offer is leaner and learns.** The cache line has its own row and one button: the choice you picked most in your last 10 answered offers (else the first keep-warm choice); the rest are in the ⋯ menu. Keep-warm buttons show the clock time keeping warm ends, counted from the turn's end, and one unit of cost (`Keep warm to 16:00 (~0.1%)` on a subscription, `($0.06)` on the API); the offer line says when the cache goes cold as a clock time too (`Goes cold in 42 min (14:55) · coming back after costs ~2%`), so neither goes stale while the row shows; Turn this off is now Don't offer again, Stop is Stop keeping warm, and the keep-warm line shows what it used, not a ping count. After 3 of the same answer it asks `Always …?` once; after 5 offers with no answer it asks `Stop offering to keep the cache warm?` once. Answers are `cold` lines in the run log, never shared and in no total.
- **An underused usage window no longer changes any decision.** When much of a window would go unused, rightsize used to lower its cost bars, which meant more hand-offs and lowerings and so more spending. It now moves nothing and says nothing. A window running hot or nearly used up works as before.
- **Usage-window shares are ranges.** The rate limits report whole percents, so a saving measured in them is not exact. On a subscription the report headline, the window rows, the minutes, the session total on the band and the idle warning now show a range such as `~0.8–1.6% of your 5-hour window`, a single value when the data is enough, or `under 1.6%` when the low end is zero.
- **Dollars on a subscription are always labelled API-equivalent.** The report's Total saved and Extra rows, the problems list, the fixed-context cost, the footer and the share message now say so, and a window share never appears with API billing.
- **Lowering effort now pays more often.** The cost model assumed every effort switch rewrites the conversation's cache. Measured switches almost all kept it, so the starting guess is now a small share (`SWITCH_MISS_PRIOR`, 10%). Learning from your own measured switches is unchanged and replaces the guess as runs come in.
- **A hand-off's main-chat cost is priced from measured hand-offs.** The main chat's brief and answer were charged at the medium-effort thinking multiple and only three reads of the conversation. Measured hand-offs show plain output near the lowest-effort multiple and several reads of the conversation, so short tasks still stay on your model and long, mechanical ones can be handed down.
- **Start on Sonnet; reviews switch to Opus for one turn.** The recommended start is Sonnet 5.5 at medium. Every review now runs on Opus at high effort or more, whatever the rating says. From a Haiku or Sonnet session the main chat itself switches to Opus for that turn and then goes back, so the review keeps the whole conversation (no subagent brief). On Opus, effort is raised to high and not lowered; from Fable a review is never handed below Opus. **Stronger model** (Q3) still decides whether the switch happens, and **Highest effort** still caps the level. The band says what happened, and the run log marks these with `rule: "review"`, `switched` and `change: "switch-up"`. A switched review doesn't push the start suggestion toward Opus.
- **Q3 Stronger model now recommends using the stronger model automatically.** Its answers are now "Use the stronger model automatically" (first, Recommended), "Ask before using it", "Stay on <model>, raise effort only" and "Ask me each time". A rule you already set is unchanged.
- The task-type guide for close calls picks Opus for reviews.
- **A follow-up keeps its task's type.** Each prompt was typed on its own, so a short follow-up in a feature task ("yes, go ahead") could be typed as a review and switch the main chat to Opus for one turn. The rating now says whether the prompt carries on the task in Claude's last reply (`continues`). A prompt that carries on is planned as its task's type, with the rated fit and size kept. A prompt that starts a new goal sets the task's type, and a prompt in a review task still gets the review rule. The run log records `continues`, and `ratedType` when the two types differ.
- **Errors from the environment no longer raise effort.** A denied permission or sandbox, no network, no login, or a program that is not installed is a Blocked stall, which more effort can't fix. These errors no longer count as signs that Claude is struggling, and no longer step an effort-lowered turn back up. The run log counts them as `blocked`.
- **The rating is less cautious about Haiku on clearly specified work.** The rating prompt now says Haiku fits mechanical edits across files, lookups and searches, and coding against a clear spec or a failing test, and keeps "no" for open-ended review, subtle bugs, design with trade-offs, writing judged on style, and long requests where a key constraint comes last. "When unsure, say no" now applies only to unclear work. Miss tracking and the Sonnet spot-checks still catch a wrong "fits".
- **The first prompt is planned on the model and context size you are really using.** rightsize read the model only after a step had run, so a session started with `--model` or `/model` was planned as Opus on its first prompt, and every first prompt was planned at 20K tokens, a resumed session included. It now reads the live model and window from Claude Code first. If no model is known it still plans as Opus, but logs that the model was unknown.
- **A route that needs more than Highest effort allows is no longer offered.** A model that needs a higher level than the ceiling was offered at the lower, capped level as if it fit. It is now dropped, for hand-offs up and down and for Claude's own subagents. A review that must run on Opus is still capped at the ceiling, not dropped.
- **Claude's own subagents now respect Pause after misses.** A model paused for too many misses on a kind of work no longer gets subagents of that kind from Claude.
- **The saving is measured against a fixed baseline.** The report rescaled the baseline by how the actual cost came out against its estimate, which hid estimates that were too low. It now uses the estimate made when the route was chosen, never changed afterward, so a task that cost more than its baseline shows a negative saving.
- **A prompt whose rating fails is left alone, and counted.** A rating that times out or can't be read is tried once more. If it still fails, the prompt runs unchanged on your model and level, and the run log gets an `unrated` line (replacing the old `overhead` line for these). `/rightsize report` counts these prompts under Not counted as savings.
- **Sonnet rates your prompts; Haiku is the fallback.** Haiku's answers sometimes ended in broken JSON, which left prompts unrated (and a review without its Opus switch). The rating now goes to Sonnet at low effort first. If that times out, is refused or can't be read, Haiku rates the prompt once; at most two calls, never a retry of each. Each call is priced with its own model, and the run line says which model rated (`rater`). **The rating now costs more**: a Sonnet call instead of a Haiku call for every prompt, and for every subagent brief of Claude's that rightsize sizes.
- **New `/config` row, Rater** (`sonnet` by default, or `haiku`): choose Haiku to keep the rating cheap. With haiku, a timeout or an unreadable answer is retried once on Haiku, as before.
- **Rater check** now checks only prompts that Haiku rated (Rater set to haiku, or Sonnet failed). A Sonnet rating is not checked against Sonnet, and does not count toward the check's every-50th.
- **A rating with a broken ending is still read.** A stray `,"}` or `,"sonnet"}` after the last field, or a comma before the closing brace, is cut and the object closed again. Nothing else is guessed: any other malformed answer is refused as before.
- **The rating prompt says how to rate effort.** Routine debugging with a clear symptom does not need a higher level than the model's medium; subtle bugs, hard reasoning and high stakes do.
- **Haiku starts out distrusted on reviews and writing.** Until your own outcomes say otherwise, Haiku on those two kinds of work counts as already at the **Pause after misses** line, so a rating that Haiku fits is not acted on from day one. The doubt is held as pseudo-outcomes that fill the 5 a task type needs; each real outcome replaces one, and after 5 only your own rate counts.
- **On a Sonnet session, debugging is not raised from the rating alone.** The rating can't tell a routine bug from a subtle one, so effort stays where it is and goes up only when the turn looks stuck (**Raise when stuck**).

- **`/rightsize share`** prints a message you can paste anywhere (LinkedIn, Slack, a DM). Once the last 30 days hold 20 rated prompts and an estimated saving of 5% or more (counted as `/rightsize report` counts it, after rating calls, and from the last Cost measurement reset), the message includes that number; otherwise it says what rightsize is and explains when the number will appear. It sends nothing, writes nothing and calls no model, and it is unrelated to the Share anonymous feedback setting.
- **Your setting wins.** A value you set yourself, in `/config` or by answering a question, is never changed or bypassed by rightsize's automatic behavior; automatic adjustments only act on settings left at their default. A value counts as set even when it is the same as the default. rightsize reads which values are yours from settings.json at session start (under `rightsize` or `rightsize@<marketplace>`; a stored value outside a row's options counts as unset), and follows changes made in `/config` as they happen. Five places that used to override you now follow this rule:
  - **Reports.** Rate limits that show a subscription or a gateway no longer replace a Reports value you set or answered. `/rightsize` notes the mismatch (for example "Rate limits look like a subscription; Reports is set to api by you."). With Reports left at its default, detection works as before.
  - **Budget pacing** moves the hand-off and lowering thresholds only when you left them at their default. A threshold you set stays as you set it, at every pace.
  - **"Ask" always asks.** A window with much left near its reset no longer raises effort without asking when the rule is "Ask".
  - **A window over 90% used** skips raises and stronger models only while Raising and Stronger model have no answer. A rule you set or answered is followed, mid-turn raises included, and the band says how full the window is.
  - **Pause after misses** (below) sets the line at which hand-downs and lowering pause, and off never pauses.
- **Twelve more settings in `/config`** (and Workflows, below), every one a picker, each applying as soon as you change it:
  - **Lowering**, **Raising**, **Stronger model**, **Cheaper model**: your answer to each of the four questions, set ahead of time (default: not set, asked the first time as before). A rule set in its row is used as it is and its question is never asked. Band rule buttons, `/rightsize settings` and "Yes, from now on" set the rows too. Set a row back to not set and the question comes back.
  - **Remember choices**: ask (as before), every session (keep answers without asking) or this session (never keep, never ask).
  - **Highest effort**: high, xhigh or max (default). rightsize never raises above it: not for a prompt, not mid-turn (which never reaches max anyway), and not for the level a helper subagent runs at. A level you are already on above it is left alone.
  - **Use Haiku**, **Use Fable**: off removes that model from hand-offs, from Claude's subagent resizing and from the starting-point comparison. Haiku still rates your prompts.
  - **Pause after misses**: off, 20%, 30% (default) to 50%; was fixed at 30%.
  - **Rate prompts from**: 3, 6 (default), 10 or 20 words; was fixed at 6.
  - **Explore close calls**: on (default) or off. Off: a close call never takes the model the task-type guide did not pick.
  - **Stuck sensitivity**: relaxed, normal (default, today's numbers) or sensitive.
- **Rater check** is now every 25, every 50 (default), every 100 or off, and **Start suggestions** is weekly (default), monthly or off. A stored `on` is not one of the new options, so it counts as unset and the default applies, which is what `on` did before.
- `/rightsize` lists every setting with its value and **(yours)** or **(default)**, in groups.
- **Band and hand-off wording** says what a cost is compared with: "About $0.04 that way vs $0.31 staying on Fable (estimated)", "That uses about 40% of the usage vs staying on Opus (estimated)", and in the result "Sent to Haiku: $0.04 vs about $0.31 staying on Fable (estimated), saved about 87%."
- **`/rightsize reset`.** It asks what to reset (Settings, Cost measurement, Both or Cancel), then asks you to confirm, since it can't be undone. `/rightsize reset <setting>` resets one, named by key (`handOff`) or title (`hand-off threshold`, any case); an unknown name gets the list of keys.
  - **Settings** writes every `/config` row back to its default (through `$.config.set`), including the four rules and Remember choices, and forgets the saved answers. Claude Code can't unset a stored value, so the rows reset are kept in a store list (`resetFields`): a row on it shows (default), not (yours), while its stored value is the default. Setting it again, in `/config` or by hand, makes it yours and takes it off the list. Resetting Reports also forgets the saved billing answer, so the rate limits read it again.
  - **Cost measurement** clears the calibration, the close-call count (`ties`), the spot-check count and the start-suggestion checks, and records `measureFrom`. Run log lines before it teach rightsize nothing: live miss rates, the starting-point check and report comparison, and the idle-warning window rate. The log file and the report's history (periods, what went wrong) still read every line; the report says "Cost measurement restarted on <date>.", and no pause is shown for rates it no longer acts on.
  - **Both** does both after one confirmation.
- **Workflows setting, asked once.** When Claude starts a workflow (it can start 10 or more agents at once, each picking its own model) and **Workflows** is still at ask, rightsize asks before the workflow starts: pause rightsize, follow my rules, or also right-size every agent. The answer is saved to the row and counts as yours; closing the question pauses for that workflow and asks again at the next. Pause is what rightsize did before: no hand-offs for the rest of the session, workflow agents left alone. Follow my rules lets hand-offs go on by your Stronger model and Cheaper model rules. Right-size every agent also rates each workflow agent that names no model (one Haiku call each) and moves it to the cheapest model that fits, under Claude's subagents, Use Haiku, Use Fable and Pause after misses; Claude's subagents set to off keeps them alone. In every case measurement stays paused after a workflow: calibration learns nothing, no saving is claimed (a moved workflow agent is counted in the report with no saving), and turns are marked `afterWorkflow`.
- **Price check is monthly or off.** "check now" is gone from the picker; `/rightsize prices` checks right away. A stored "check now" is not one of the options now, so it counts as unset and monthly applies.
- `scripts/check-settings.mjs` checks that every row in plugin.json has a matching entry in `settings.ts`, a parse in `register.tsx`, an entry in the README's `/config` list and a test. Run it with the other checks in CONTRIBUTING.md.
- **Opt-in anonymous sharing.** After 20 rated prompts, rightsize asks once whether to share anonymous numbers with its author. On a yes, at most once an hour it sends what the run log gained since: task types, models and levels, token guesses, conversation size, estimated and real costs, outcomes (rework, step-ups, a count of mid-turn raises), Sonnet checks and 👍/👎, with times rounded to the hour, a random install ID and a one-way code linking each 👍/👎 to its prompt. Prompts, replies, code, file names, paths, tool and server names, raise reasons and session IDs are never sent. **Share anonymous feedback** in `/config` (off by default) turns it on or off; turning it on again starts a new install ID. Nothing is sent while `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set. The README has a Privacy section.
- **Haiku's rating is scored against what happens.** rightsize counts, per task type and model, when the rating turned out wrong: a hand-off that needed rework (more than one subagent call), a lowered turn that stepped back up or was raised mid-turn, an unchanged turn raised mid-turn, a 👎, or a Sonnet check that disagreed. The matching hits are a hand-off without rework, a lowered turn that held, a 👍 and an agreeing check. A type needs 5 outcomes on a model before its own rate counts, else the model's rate across types does (also from 5). Only the last 30 days of the run log count, and nothing leaves your machine. At a 30% rate, hand-downs of that kind of work to that model stop, and so does lowering effort on it, until the rate falls back under 30%.
- **Starting-point estimates weigh that rate.** Where Haiku's rating of a start's model has been wrong for a task type, that share of its prompts is replayed as if the model had been rated unable, so the cost and the count of prompts sent to a stronger model rise with it.
- **Sonnet spot-checks Haiku.** On every 50th rated prompt (the first check on the 50th), rightsize sends the same rating prompt to Sonnet at low effort in the background; the prompt is never delayed. The answer is logged as a `check` line carrying Haiku's `fit`, Sonnet's `fit` and the check's cost, which the report counts as overhead. A check that fails or can't be read adds only its cost. A check's cost that lands in the ledger while a turn runs is left out of that turn's cost. **Rater check** in `/config` (on by default) turns it off.
- **👍 and 👎 in the band.** A hand-off's result and a lowering now show 👍 and 👎. Pressing one writes a `feedback` line to `rightsize-runs.jsonl`, takes the buttons off the band so it can't be pressed twice, and shows a short thanks. Nothing is sent anywhere. Each run line now carries an `id`, which the feedback line names as `ref`.
- `/rightsize report` says how often Haiku's judgement was wrong (and the hand-downs and lowerings paused for it), and `/rightsize` shows the Rater check setting. Check and feedback lines are not rated runs.
- **Start suggestions.** Once a week at session start, rightsize estimates what the last 30 days of rated prompts would have cost from Sonnet and Opus at medium and high, replaying each prompt through its own planner with your rules, thresholds and calibration. The band suggests switching with `/model` when another start is at least 15% cheaper (25% while it has under 20 measured main-chat runs) and sends no more than 1 prompt in 10 to a stronger model, or when over 15% of prompts on the current start needed a stronger model or a mid-turn raise. It waits for 50 rated prompts in 30 days and 20 on the current start. **Not now** quiets the same suggestion for 14 days; **Stop suggesting**, or **Start suggestions** in `/config`, turns it off. `/rightsize report` always shows the comparison. rightsize never changes the model itself.
- Run log lines carry `normal` (the session's own level, before rightsize's change) and `context` (the conversation's size when the prompt was rated), which the starting-point check replays from. Older lines use the run's level and the median size.
- The README recommends starting on Sonnet 5.5 or Opus 5.5 at medium.
- **Subscription wording leads with usage.** On a subscription, `/rightsize report` puts the share of the 5-hour window kept first, then the share of usage saved, with dollars marked API-equivalent; a line at the top says dollar amounts are API-equivalent. Before runs show the window rate, the share of usage leads. A hand-off's result says "API-equivalent" instead of "At API prices".
- **Idle warning on a subscription.** The idle question now comes up on a subscription too. It gives the cost as a share of the 5-hour window (from the last 30 days of runs) with API-equivalent dollars beside it, or API-equivalent dollars alone until runs show the rate. The **Idle warning** bar is compared in API-equivalent dollars.

## 0.6.0 (2026-10-24)

- **Estimates follow the work each model does at each effort.** The same task takes different output tokens and tool calls depending on the model and its level: Opus at low effort takes far fewer steps than at medium, Haiku writes more than Sonnet, Fable more than Opus. A table of work per model and level (Sonnet as the baseline, so its estimates do not change) now scales the rated output tokens and steps for the main chat and for subagents. The values come from Anthropic's cost and intelligence guide and Artificial Analysis, with guesses interpolated; calibration corrects them.
- **Close calls are broken by a task-type guide that fades as runs come in.** When two models that could take the work land within 25% of each other in estimated cost, rightsize no longer lets noise pick the cheaper one: it takes the model a task-type table names (Haiku for lookups, searches, bulk edits, extraction and summaries; Sonnet for writing, review, features, debugging, refactors and the rest; Opus for design), or the stronger model when the table's pick is not among them. The 25% shrinks to nothing as the two routes' runs are measured (zero at 20 runs, counted on the one with fewer). It only chooses among routes that already pass the hand-off share or fit the work; it never makes a hand-off or overrides a "would struggle". One close call in five takes the other route instead, counted in the store (`ties`), so both get measured. The same rule picks the model for Claude's own subagents. Run log lines carry `tie`, and `/rightsize report` says how many close calls the guide decided and how many were explored.
- **Calibration starts over once.** It is stored under a new key (`calibration-v2`) because the old ratios were learned against the old estimates and would count the change twice. The old key is ignored, not read or deleted.

## 0.5.0 (2026-10-23)

- **Claude's moved subagents are measured and learned from.** Each one's own requests are priced, and when it answers (often after the turn that started it, for a background one) rightsize logs a `subagent` line with its real cost and its raw estimates on its model and on the parent's, and teaches `<type>:subagent`, `:<model>` and `:<model>:<level>` calibration from it. The next sizing uses those numbers. A stopped subagent is logged and teaches nothing; a resumed one counts again from zero.
- `/rightsize report` counts these subagents ("N subagents Claude started ran on a cheaper model") and adds their saving: the real cost scaled by the parent's estimate over the chosen model's.
- A subagent's first request no longer slips through at Claude's effort when the engine starts it before the spawn settles: a step from a subagent whose id is not known yet is matched to the pending spawn by its description and type in the agent list. This covers the hand-off's subagent and moved ones.
- The rating no longer asks for `size`; routing has not used it since model and effort were rated together. Older replies that still carry it read as before.
- Raise when stuck: a Bash command run again with a new `description` counts as the same call, so "the same tool call failed twice" fires. Found in a live session, where three failing `false` calls only tripped "3 tool calls failed".
- The fixed-context advice in `/rightsize report` names the fixes for its biggest parts (skills and plugins, MCP servers, CLAUDE.md, agents) instead of always leading with MCP.
- The idle question says "1 minute", not "1 minutes".
- **Idle warning.** On API billing, when a session under 200K tokens sat idle past the cache's life, rightsize asks before the next prompt (short ones too) writes the whole conversation to the cache again, with the cost of sending, of /compact, and that /clear is free. Hold it and the prompt goes back in the box. Each session's last turn is kept in the store, so a resume days later is caught too. Asked once per idle gap. **Idle warning** in `/config` sets the bar (over $0.10 by default) or turns it off. Subscriptions are left to Claude Code's own warning, and sessions over 200K to its idle compaction.
- **Fixed context in the report.** Each run line logs its main-chat requests and the tokens every request carried that rightsize can't trim: loaded MCP tools (by server), CLAUDE.md and memory, agent descriptions, skills and commands, with what re-reading them from the cache cost at least. `/rightsize report` adds them up for 30 days, names the biggest MCP servers, and says how to cut it.
- **Raise when stuck.** When a turn shows Claude is stuck, effort goes up one level for the rest of that turn. The signs: the same tool call failing twice, 3 tool calls failing, the same call running 3 times, or a turn passing 3x the rated steps (at least 15). Each sign counts once a turn; at most two raises a turn, never to max. It follows the Raising rule: automatic raises without asking, "Ask" (or no rule yet) asks mid-turn, never does nothing. A refused call is not a sign; a hand-off's main chat is not raised; nothing is raised when a usage window is over 90% used. Raised turns teach calibration nothing and claim no saving; run log lines carry `escalations`, and `/rightsize report` lists them under what went wrong. **Raise when stuck** in `/config` turns it off.
- `tsc` passes on the tests again: the fake engine's rate limits carry `resetsAt`.
- **Budget pacing.** On a subscription, rightsize moves its thresholds by how fast the 5-hour and 7-day windows are being used (share used over share of time gone), using whichever window would stop you first. On pace to run out early (over 1.2): hand off under 85% of staying and lower under 97%. Much of a window left near its reset (under 0.6): hand off only under 50%, lower only under 80%, and raise effort without asking when the rule is "Ask". Over 90% used: hand off under 95%, lower whenever it fits, and skip raises and stronger models. The first 15% of a window is not paced. The band says when pacing changed a decision, and run log lines carry `pace`. **Budget pacing** in `/config` turns it off. Choices set to never or stay are kept.
- Run log lines carry the rater's guesses behind each estimate (`read`, `write`, `steps`), so a bad guess can be told from a bad cost model.
- **Claude's own subagents.** When Claude starts a general-purpose subagent without naming a model, it would run on Claude's own model. rightsize now rates the subagent's brief with Haiku and runs it on the cheapest weaker model that fits, at that model's level, when that costs under the hand-off threshold. It never picks a stronger model, and it leaves alone subagents that name a model, other agent types (they may set their own), forks, workflow agents, resumes, teammates and subagents started by subagents. The band says so (`Ran Claude's subagent on Haiku (low) instead of Opus.`), and run log lines carry `resized`. **Claude's subagents** in `/config` turns it off.
- A hand-off now counts as taken when Claude's Agent call names the full model id (`claude-haiku-5-5`), not only the alias.
- **Workflow guard (ultracode).** Once Claude runs a workflow in a session, rightsize stops handing work off for the rest of that session, and turns from then on teach calibration nothing and claim no saving: a workflow runs on in the background, so its agents' cost lands in later turns too. Prompts are still rated and effort still changes. `/rightsize report` lists these turns on their own line; run log lines carry `workflows` and `afterWorkflow`.
- Main-chat calibration is kept per task type, per model and per model at each level, like hand-offs: expensive runs at high no longer move the estimate for low.
- **Model and effort together.** The rating gives each model's own level (or says it would struggle), and the cost model prices every model at its level. On Opus at medium, work Opus needs high for can go to Haiku at high instead of raising Opus. Of the cheaper models that fit, the cheapest route wins; the comparison counts the switch a raise would cost. Hand-downs no longer need the work rated "bulky": the cost decides. The older one-level rating still reads.
- The hand-off's subagent runs at the level its model needs: rightsize sets its effort on each of its requests, instead of relying on the note. Other subagents keep their own level.
- Hand-off calibration is kept per task type, per model and per model at each level; each finer key starts from the one above it.
- `rightsize-runs.jsonl` lines carry each model's rated level (`fit`) and a hand-off's real subagent level (`subLevel`).
- **Hand-off threshold** (default 70%) and **Lowering threshold** (default 90%) in `/config`: how much cheaper a subagent or a lower effort level must be before rightsize uses it. `/rightsize` shows the values in use.
- Calibration from sessions running at the same time is merged, not overwritten: each save adds its new runs to the stored record.
- A lowered turn that stepped back up no longer counts toward calibration, since part of it ran at the normal level.
- A band above the prompt (CLI and desktop app) shows what rightsize did, with buttons to undo it, clear a session switch, change the rule for that case, or close it. It also shows a hand-off's result, which no longer takes a transcript line. **Band** in `/config` (or ⋯ on the band) sets when it shows: when it acts (default), always, or off.
- Billing is read off each response's rate limits: five-hour and seven-day windows mean a subscription, a spend limit means a gateway. rightsize asks once only when they show nothing, and keeps the answer across sessions.
- Each turn's actual cost comes from the session's cost ledger (the `/cost` total), leaving out the Haiku rating call. Where there is no ledger, it prices the token counts from `prices.json`. Cache writes are priced at the 1-hour TTL by default.
- Every rated turn is logged to `rightsize-runs.jsonl` with its session, the change made and suggested, the rating call's cost, the rate-limit windows, its duration and its subagent calls.
- `/rightsize report`: prompts rated and changed, the saving net of rating calls, the share of the usage window it kept for subscribers, and what went wrong, for this session, 7 days and 30 days.
- The monthly price check is claimed before the page is fetched, so two sessions starting at once check only once. A failed check gives the claim back and stays due.
