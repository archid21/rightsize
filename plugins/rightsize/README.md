# rightsize

By [Archi Dubey](https://github.com/archid21), MIT license. Full guide: https://github.com/archid21/rightsize. Feedback: hello@aivalue.blog (subject: rightsize)

**Make every Claude token count.**

rightsize sends each prompt to the cheapest model and effort that does the job, raises effort only when Claude is actually stuck, and keeps your cache and context from costing more than they should. No profiles, no tuning: one rule set, two switches.

## Why use it

**Same outcome, lower cost from an Opus start.** Routine work goes to Haiku or Sonnet helpers and lower effort; Opus keeps the work that needs it. On our coding benchmark it matched Opus at up to 30% lower cost (API-equivalent).

**Effort follows evidence, not guesses.** A rating never raises effort on Opus or Fable at prompt time. Effort goes up mid-turn only when the turn shows trouble: repeated failures, a loop, or two fixes in a row that leave the tests red. You stop paying for high effort that buys nothing.

**Stronger reviews from a Sonnet start.** Reviews switch to Opus for that one turn and come back. You get Opus-grade review without switching models yourself. If your default is Sonnet you may spend more: on our coding benchmark, about 1.4x to 2x what Sonnet alone costs, almost all of it from reviews. Your cost depends on how many reviews you run.

**It learns which routes to trust.** Every hand-off, lowering, test run and thumbs rating scores the rater per kind of work and model. A model that misses on reviews stops getting reviews until your own outcomes say otherwise.

**Cut cache and compact costs.** Keeps the cache warm when that is cheaper than coming back cold, warns as your context fills, steps aside for Claude's idle compact, and compacts only when the saving beats the cost.

**rightsize works better with whatsnext.** rightsize decides when a compact pays. [whatsnext](https://github.com/archid21/whatsnext) decides what to keep: it saves a handoff note first, so a compact retains the details that matter. rightsize asks it for that handoff before the cache goes cold and uses its compact text for **Compact now**. rightsize works on its own too, and uses Claude's own compact when whatsnext isn't installed.

★ Needs whatsnext.

Before a prompt is sent, rightsize asks a rater (Sonnet at low effort by default, or Haiku: see **Rater**) which effort each model would need for it, or whether a model would struggle, and how big the work is. A cost model then prices each model at its own level, counting the work that model does at that level, and picks the cheapest route that fits, which can change the model and the effort together. Savings are estimates against a baseline: rightsize's own estimate of staying on your model and effort, made when it chose the route and never changed afterward.

Your setting wins: a value you set in `/config`, or set from the band, is never changed or bypassed by the mod's own behavior. **Ask before changing** (a plain row in `/config`, off by default) decides each of the four cases while its rule row is not set: off acts, on asks; a row you set beats it. **Mode** (the first row) can be set to watch only, which rates and plans every prompt and applies nothing.

## Install

Needs Claude Code 2.1.287 or newer (2.1.286 in the desktop app). rightsize states this requirement and does not check it. In a terminal:

```
claude plugin marketplace add archid21/rightsize
claude plugin install rightsize@archid21 --scope user
```

Or inside a session: `/plugin install rightsize --marketplace archid21/rightsize`. Then start a new session and type `/rightsize`. If the settings pane opens, it works. Or paste this into any Claude Code session: "Install the rightsize plugin from GitHub. Run `claude plugin marketplace add archid21/rightsize`, then `claude plugin install rightsize@archid21 --scope user`, and tell me if either fails."

## The four cases

There are four cases, and each has a rule row in `/config`:

- **Lowering**, when a prompt needs less effort: ask me · lower automatically · never lower.
- **Raising**, when it needs more effort on the same model: ask me · raise automatically · never raise.
- **Stronger model**, when a stronger model than yours fits better, or a review runs on Opus for one turn: ask first · always send · stay, raise effort only · ask each time.
- **Cheaper model**, when a task could run on a cheaper model: ask first · always send · stay, lower effort only · ask each time.

**A row left at not set means Ask before changing decides.** Off (the default): lower automatically, raise automatically, always send, and nothing asks. On: ask me and ask first. The band says so the first time each case comes up in a session, for example `The default decided (Cheaper model); ⋯ changes it.` The other rules for that case are in the band's ⋯ menu; picking one sets the row.

**An "ask" rule opens its own dialog** (every case while Ask before changing is on, and any row you set to an ask value). It is the only kind of question that holds your prompt. It waits **Question wait** (30 seconds, 1 minute or 2 minutes). With no answer, the prompt runs unchanged: no raise, no stronger model, no subagent, nothing saved. `/rightsize settings` still asks the four questions, one after another, for anyone who wants to set rules that way, and sets the rows from the answers.

**The Remember question follows only a rule you set yourself,** from the band's ⋯ menu or `/rightsize settings`. After your first such rule it asks on the band whether to keep your rules in every session. A rule Ask before changing supplied is never asked about.

Every other question is a row on the band, and the work does not wait for it. Remember choices and Reports (asked only when no response shows how you pay) show when the turn ends and stay until your next prompt. Stuck shows during the turn and goes when it ends; the turn goes on at its effort, a Raise applies from its next request, and a stuck helper whose Stuck question gets no answer goes on at its effort too. Workflow is asked at each Workflow call until you answer, with rightsize paused for that workflow. Press a number key or click an option to answer, or × to dismiss. Unanswered, each keeps its safe default: no raise, this session only, API prices, rightsize paused. Where the band cannot show (Band set to off, or the mobile app), these are timed dialogs.

## How it decides

- **Your setting wins.** Automatic adjustments, and rightsize's fixed values, act only on settings left at their default. Budget pacing moves a bar only when you did not set it; a window nearly used up skips a raise or a stronger model only while its rule is not set; rate limits never change **Reports** once you set it; an "ask" rule always asks. `/rightsize status` shows Ask before changing on its first line and lists the settings you changed.
- **Watch only.** With **Mode** set to watch only, every prompt is rated and planned and nothing is applied. The band says what would have happened, for example `Watching: would send this to a Sonnet subagent at medium effort. ... Mode in /config turns it on.` `/rightsize report` has a `Watch only:` line: how many prompts would have changed and what that was estimated to save.
- **It plans from the session you are in.** The model in use and the conversation's size are read from Claude Code on every prompt, the first of a session included. A conversation of unknown size is planned at 20K tokens. If no source names a known model, it plans as Opus and logs that the model was unknown.
- **Every prompt is rated as you enter it.** Short ones too: a one-word follow-up is rated in its task. The rater is told how the task began (the first 600 characters of the prompt that started it, its type, how many prompts it has had). A request over 6,000 characters is shown as its first 4,000 and last 2,000 characters with a marked cut. The rater is told that a bulk edit, extraction or summary with a clear rule fits Haiku at medium.
- **Missing context is no reason to downgrade.** When the request was cut, or a task is in progress and Claude's last reply could not be read, no lowering or hand-down is made, and the prompt runs as it is. Raising effort and a stronger model are not affected. The run log carries `unsure`.
- **A prompt that can't be rated is left alone.** A Sonnet rating that times out, is refused or can't be read is tried once on Haiku. If that fails too, the prompt runs unchanged and the report counts it under Not counted as savings. A rating may take at most 12 seconds in all (Sonnet at most 9; Haiku gets what is left, or is skipped under 2 seconds).
- **Effort changes are free on the current models.** Anthropic's docs say an effort change keeps the prompt cache on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 with the Claude API or a Claude subscription (Claude Code 2.1.260 or later), so rightsize prices a switch as free and lowers whenever the lower level costs less. It still logs every switch with whether the cache survived: where a change does rebuild the conversation (a gateway, Amazon Bedrock, Google Cloud's Agent Platform, an older model), the measured misses price the switch again. Auto-lowered turns stay at the lower level for the whole turn; a tool error brings your normal level back.
- **Changing the model means a helper, except for a review switch.** The main chat keeps its model and cache. A hidden note beside your prompt asks it to: (1) write a brief with a "Done means" list, (2) check the helper's result against it, (3) send rework notes, at most the task's chances (2), (4) report how it went. If the helper still fails after its chances, the main chat finishes the work.
- **Steps only you can approve stay in the main chat.** A helper must not push, publish, release, deploy or merge from the shell, or call an MCP tool whose name starts with send, publish, deploy, merge or post, because another agent's message is not your approval. rightsize denies those calls (`tool.call`). It also denies the calls of a helper that was stopped and sent back, rework past the chances, and a cheaper helper's calls past its call cap (25 for Haiku, 40 for Sonnet). A request that is mainly such a step isn't handed off.
- **Reviews run on Opus at high effort or more.** A review needs the whole conversation, so from Haiku or Sonnet the main chat switches to Opus for that one turn, then goes back to your model (Opus writes the conversation to its cache once, which the estimate counts). On Opus, effort is raised to high and not lowered. From Fable a review can go to an Opus helper; it is never handed below Opus. **Stronger model** decides whether the switch happens. A switched review runs at **Highest effort** at most. The band shows the cost multiple before the turn. A switched review does not count toward a starting-model suggestion.
- **A follow-up keeps its task's type.** A prompt the rater types as carrying on the task is planned as that task's type, so a one-line follow-up in a feature task is not sent to Opus as a review. In a review task, a follow-up the rater itself types as something else (a lookup, a fix) is planned as what it is, not switched to Opus.
- **Where you start decides the moves.** On Opus or Fable, every task but a review runs at low effort, whatever the rating says (on our benchmark low passed as often as medium); a rating never raises effort there, and the stuck signs do the raising mid-turn. On Sonnet, effort holds; a rated raise is taken only for a task rated hard (high or more) with 20 steps or more, never for debugging. On Haiku, mechanical work stays, and debugging, features, refactors and writing switch the main chat to Sonnet for that turn, the way a review switches to Opus, but this one move always asks (even under **Stronger model** "always send"): the band shows both costs and nothing switches until you answer.
- **Handing work down needs a clear saving.** Hand-downs start only from an Opus or Fable session; from Sonnet the brief and the check cost more than Haiku saves. A Haiku helper takes mechanical work only (lookups, searches, bulk edits, extraction, summaries); any other helper needs a task of 20 rated steps or more. A helper is used only when its estimate, counting the brief, report, check and likely rework, is under 70% of the cost of staying at the level the work needs (85% while a usage window runs hot, 95% when nearly used up: **Budget pacing**). Lowering effort needs the lower level under 90% of staying, counting the cache it may rewrite. Neither bar has a row. The rating alone is the evidence for work the research did not cover; there is no minimum of logged tasks. **Highest effort** caps every raise, including a helper's level; **Use Haiku** and **Use Fable** turn off work sent there.
- **Close calls go to the model suited to the task.** When two models that fit are within a band of each other in cost, rightsize picks by task type: Haiku for lookups, searches, bulk edits, extraction and summaries; Sonnet for writing, features, debugging and refactors; Opus for design and reviews. The band starts at 25% and shrinks to nothing at 20 measured runs. A close call always takes the task-type pick.
- **The rating is scored against what happens.** Per task type and model, these count as misses: a hand-off that needed rework, a lowered turn that stepped back up after a tool error or was raised mid-turn, an unchanged turn raised mid-turn, a test run that fails at the end of a turn (main chat or helper) after a lowering or hand-down, a next prompt the rater marks as correcting the reply (the cheaper route before it is the miss), a 👎, and a Sonnet check that disagreed. Hits are the same without the problem, a 👍, and an agreeing check. A type needs 5 outcomes on a model before its own rate counts, else the model's rate across types does. Research priors start some work with a built-in doubt that counts as 10 tasks (Haiku on reviews 0.8, Haiku on writing 0.5, Sonnet on reviews 0.3 as miss rates); each real outcome pushes one out. Over the last 30 days, a rate at or over 20% stops hand-downs and lowering for that kind of work on that model, until it falls back under.
- **Sonnet spot-checks Haiku.** On every 20th prompt rated by Haiku, Sonnet rates the same prompt in the background. A disagreement that Haiku said a model does the work and Sonnet says it would struggle counts as a miss. It never delays your prompt.
- **It raises effort when Claude gets stuck.** Normal: the same call fails twice, 3 calls fail, the same call runs 3 times, the turn passes 3x the rated steps (at least 15) while its last 10 calls show no progress, or two fixes in a row leave the tests red (a test run fails, Claude edits, a run fails again, twice; how many calls a fix takes does not matter). Progress is a file edit or write that worked, a test run that passed, or mostly new calls (reading new files counts), so a long turn that keeps working through a big plan is left alone, and one that stalls later is still caught. It raises one level for the rest of the turn, at most twice, never to max and never above **Highest effort**, following your Raising rule. Errors from the environment (a denied permission or sandbox, no network, no login, a missing program) and calls you refused don't count. A rating alone never raises effort on Opus or Fable (reviews excepted), and not for debugging on Sonnet: there, effort goes up only when the turn shows it is stuck. A lowered turn stays lowered for its whole length; a tool error brings the session's level back.
- **Keep warm runs until your usual start while the row is not set.** When a turn ends in a session where a cold return would cost at least the Idle warning amount, $0.50 by default and while Idle warning is off (about 65K tokens on Opus, 130K on Sonnet; API-equivalent dollars on a subscription too), rightsize acts on **Before the cache goes cold**. While the row is not set it keeps warm until your usual start time (the median time of your first prompt over 14 days, at most 8 hours; 9:00 until 5 days of data). Just before each expiry rightsize sends one small request (`Reply with the single word OK.`), which refreshes the cache. The band shows a status row, `Warm until 9:00 · ~0.3% so far` (`$0.00 so far` on the API, `~0% used so far` on a subscription, before the first request), with **Stop keeping warm**, and `Don't keep warm again` in ⋯ (sets the row to off). It stops when you send a prompt, press Stop, a request fails, the end time comes, or keeping warm would cost more than coming back cold: that cap is never passed. The `ask` value (an offer on the band 5 minutes after the turn, with a learned button, `Always …?` and `Stop offering?`) is there for anyone who sets it. **save a handoff** sends `wrap up` once for whatsnext (compacts without it, or in a project where `whatsnext init` has not been run); **compact** compacts once (with whatsnext, using its instructions).
- **Keep warm is credited for what it prevents.** When you send a prompt after the time the cache would have gone cold and its first request read at least about 80% of the conversation from the cache, one `warmSaved` line records what coming back cold would have cost. A run you never come back to is pure cost. The report's Keep warm line shows runs, what they saved, what the requests cost and the net.
- **An idle warning never holds your prompt.** When a prompt is sent after the cache expired (1 hour, or 5 minutes per `prices.json`) in a session, and rewriting costs over the row's bar (default over $0.50), the band notes it beside what rightsize did: `Idle 2 h: the cache went cold, so this prompt writes the conversation (~120K tokens) again, ~1.2% of your 5-hour window more than warm; /compact first would have cost ~0.3%.`
- **A context-size warning.** When a conversation first reaches 40, 50, 60, 70, 80 or 90% of the window, the cache row says so with a **Compact now** button, once per step; steps at or above Claude Code's own auto-compact point are skipped. Nothing compacts unless you press the button. ⋯ has **Why?** and **Don't show again**. It reads the context size and `autoCompactThreshold` from the session's usage.
- **Advice to compact before your 5-hour limit.** When a turn ends with your 5-hour window at 90% or more, over 30,000 tokens of conversation, and the reset further off than the cache lives, the band says a compaction now (the cache is warm) would save money after the reset: `Near your 5-hour limit, resets 21:40. Compact now to save ~$0.31 after the reset.` (`~3% of your next window` on a subscription). It shows once per 5-hour window, and only when the saving is above zero. **Compact now** compacts with fixed instructions (keep the task, decisions, open questions, file paths and next steps; drop tool output and dead ends), or with whatsnext's instructions when whatsnext is installed and started in the project; nothing is compacted unless you press it. ⋯ has **Why?** and **Don't show again** (kept). It follows the **Cache** setting, and in watch only mode it is written to the log, not shown.
- **It paces your usage windows.** On a subscription, rightsize divides the share of a window used by the share of time gone, and acts on the window that would stop you first. Over 1.2: the hand-off bar moves from 70% to 85% and lowering from 90% to 97%. Over 90% used: hand-off 95%, lowering whenever it fits, and raises and stronger models skipped while their rules are not set. Under 1.2 nothing changes, and the first 15% of a window is not paced. A bar you set stays as set. When pacing moves a bar the band says which, for example `hand-off bar 70% → 85%`.
- **Claude's own subagents are right-sized too.** A general-purpose subagent started without a model is rated and may run on the cheapest weaker model that fits, under the hand-off threshold. It never moves to a stronger or paused model. **Claude's subagents** turns it off.
- **Workflows are your call.** When Claude starts a workflow (ultracode), rightsize asks at each Workflow call until you answer, with rightsize paused meanwhile, and saves the answer as **Workflows**. After a workflow, calibration learns nothing and no saving is claimed.
- **When you step up, rightsize steps aside.** If you switch to a stronger model (`/model opus` from Sonnet) or raise the effort, rightsize pauses: it changes neither the model nor the effort, hands nothing off and moves no subagent until you resume. The band says `Paused: you switched to Opus.` once, with **Resume rightsize**, and the status line keeps showing the pause; × hides the row but keeps the pause. Resume with the button or `/rightsize resume`, and rightsize plans from the model and effort you have then. If you go back to the model and effort you had before, or lower, it resumes on its own. A step down never pauses it, and neither does its own review switch. Cost tracking, keep warm and the warnings go on; paused prompts claim no saving. A model change is seen when you send the prompt; an effort change on the prompt's first step, so that prompt is rated but nothing it planned is applied.
- **Long runs and whole tasks.** A run's cost grows more slowly than its steps; rightsize learns by how much from your runs and applies it only once it clearly cuts the estimate error. The report compares each finished task's cost with the sum of its estimates, from 5 finished tasks.
- **Calibration.** After each rated turn, rightsize reads the real cost from Claude Code's cost ledger (the `/cost` total), leaving out the rating call, and moves its estimates toward it, per task type, route, model and level. After 20 runs the measured average replaces the guess. `prices.json` is compared with Anthropic's pricing page every 30 days.

### The band

A band above the prompt (CLI and desktop app) shows one labelled row per topic, at most three: **Prompt**, **Cache** (the keep-warm status or offer) and a question. Buttons: **Retry at original effort** or **Clear**; **Run on <your model>** after a hand-off or a switch (runs that prompt once without rightsize); **Resume rightsize** after you stepped up; **⋯** for the rest; **×** to close. Each route says why, and a move to a cheaper model gives rightsize's confidence (`Confidence: low.` until 10 of your own tasks are logged on that route).

The **⋯** menu holds the other rules for the case that just came up (picking one sets the row), the cache choices, **Mark this 👍 (right call)** and **Mark this 👎 (wrong call)**, and when the band shows. A mark is written to the run log on this machine and tunes rightsize's choices there; it is not sent anywhere. After a hand-off the band shows the result, for example `Sent to Haiku. $0.04 vs ~$0.31 on Fable (~87% saved).` on the API or `Sent to Sonnet. ~28% of Opus usage.` on a subscription. From the session's 3rd rated prompt, every band ends with the session's running total, for example `Session: ~$0.84 saved`.

## Choosing a starting model

Start on Sonnet 5.5 at medium. It handles lookups, searches, edits, features, debugging and writing well, for much less than Opus. rightsize moves what Sonnet is weaker at to Opus: a review runs that one turn on Opus at high effort or more, then the chat goes back to Sonnet; a prompt the rating says Sonnet would struggle with goes to an Opus helper. Start on Opus 5.5 at medium only if most of your work is design or review. Avoid Opus at low (frequent raises re-write the cache) and Fable (the highest total).

**A day-one tip.** On your first session on an Opus start with fewer than 50 rated prompts, the band shows once: `Starting tip: most work runs as well on Sonnet 5.5 at medium for well under half the usage of Opus. Reviews still run on Opus, and work Sonnet would struggle with goes to a stronger helper. Switch with /model sonnet.` The button **Switch: /model sonnet** puts the command in the prompt box and you press Enter; **Not now** closes it. rightsize never changes the model itself.

**A weekly suggestion from your log.** Once a week (or a month: **Start suggestions**) at session start, rightsize estimates what the last 30 days of rated prompts would have cost from Sonnet and Opus at medium and high, its own changes counted and Haiku's miss rate on the start's model weighed in. The band suggests a switch when another start is at least 15% cheaper (25% while it has few measured runs) and sends no more than 1 prompt in 10 to a stronger model, or when over 15% of prompts needed a stronger model or a mid-turn raise. It needs 50 rated prompts in 30 days and 20 on the current start. **Not now** quiets it for 14 days; **Stop suggesting** turns it off. Switch with `/model`.

## One rule set

rightsize has one rule set and no profiles. The values a profile used to hold are fixed: hand-off threshold 70%, lowering threshold 90% (both moved by **Budget pacing** when a usage window runs hot), a pause at 20% misses with no minimum of logged tasks, close calls decided by the task-type guide, a helper call cap of 25 for Haiku and 40 for Sonnet, Sonnet checks every 20th Haiku rating, and 2 chances per task for a struggling helper. Two of them still have a row: keep warm until your usual start (**Before the cache goes cold**) and a switched review at up to **Highest effort**. A value stored for a row an earlier release had (Hand-off threshold, Lowering threshold, Explore close calls, Pause after misses, Helper call cap, Rater check) is ignored. **Hand-offs** turns helpers off and leaves effort changes on; **Ask before changing** makes every move ask first. A Quality, Balanced or Economy profile saved by a release before 0.9 is read once: Quality as Ask before changing on, the others as the defaults.

**Every rating starts from rightsize's research.** Before your own log says anything, each kind of work on Haiku and Sonnet starts from a built-in miss rate that counts as 10 tasks: a cheaper route can be used from the first day where the research found it reliable (lookups, searches, routine edits, features, refactors, debugging) and is held back where it did not (reviews on Haiku or Sonnet, writing on Haiku). Each task you run takes the place of one of the 10; after 10, only your log counts.

## Commands and settings

- `/rightsize` opens a settings pane that lists every setting in `/config` with its value (Mode, Routing, Hand-offs, Ask before changing and Cache first, then the Advanced ones). A row you set is marked `(yours)`, one you have not `(default)`. A pick takes effect at once. Where no pane can be drawn, or on the mobile app, it asks instead.
- `/rightsize status` shows Ask before changing on its first line, the settings you changed, what the fixed values and your settings add up to, the session switch, the measured runs and the cache-switch results.
- `/rightsize help` lists every command. `/rightsize share` prints a message you can paste to tell others about rightsize; it sends nothing.
- `/rightsize report` shows what rightsize did, as plain text in the terminal and as Markdown in the desktop app. Sections, left out when empty: a headline for the last 30 days; a table for this session, 7 days and 30 days (Total saved after rating costs, window shares on a subscription as ranges, share of cost saved, Extra spent on harder prompts, then what was kept, lowered, raised and sent); Watch only (when Mode is watch only: how many prompts would have changed and the estimated saving); Starting point; Fixed context (the tokens every request carries, largest part first); Accuracy (miss rate, spot-checks, paused hand-downs, estimate error); Not counted as savings; Keep warm; Time (per task: Claude's time, time to done, the rating's delay, cheaper routes against staying; reported, never used to choose a route); Whole tasks (from 5 finished tasks); Next steps; and a footer. Savings are estimates against the baseline, can be negative, and on a subscription dollar amounts are API-equivalent: what the same use would cost on the API, not your bill. The footer also shows how Share anonymous feedback is set.
- `/rightsize settings` asks the four questions and sets their rows from your answers. `/rightsize retry` puts the last lowered prompt back in the box at normal effort (file changes are not undone). `/rightsize clear` drops a session switch. `/rightsize resume` ends a pause after you stepped up. `/rightsize prices` checks prices now.
- `/rightsize reset` asks what to reset (Settings, Cost measurement, Both or Cancel) and confirms. `/rightsize reset <setting>` resets one, named by key (`handOff`) or title.
- `/mods` turns the mod on or off.
- Changing settings: in a terminal, `/config` applies a change at once. The desktop app has no `/config` menu: change settings from a terminal (`claude plugin configure rightsize@archid21 --values-stdin <<< '{"handOff":"60%"}'`), then quit the app and reopen it.
- `/config`, then rightsize. Every row is a picker. Every row except Mode, Routing, Hand-offs, Ask before changing and Cache is titled "Advanced · ..." in `/config`; the list gives the name.
  - **Mode** (act or watch only, default act): watch only rates and plans every prompt, applies nothing, and the band says what it would have done. Use it for a week to see rightsize's calls on your own work.
  - **Routing** (on or off, default on): effort changes on your main chat (lowering, raising, a session switch), the review switch to Opus for one turn, and raising effort mid-turn when Claude looks stuck. Off: none of those, and **Raise when stuck** is not used. With Routing and Hand-offs both off, no prompt is rated and nothing is spent on rating.
  - **Hand-offs** (on or off, default on): handing work to a helper subagent, and moving Claude's own subagents to a cheaper model. Off: neither; with Routing on, an effort change takes the place of a hand-off. With Routing and Hand-offs both off, no prompt is rated and nothing is spent on rating.
  - **Ask before changing** (off or on, default off): on, every move rightsize would make on its own asks first; a rule row you set still wins for its case. A Quality profile saved by an older release reads as on until you set this row.
  - **Cache** (on or off, default on): keep warm, the cache offer, a handoff or compaction before the cache goes cold, and the idle warning. Off: none of those, nor the advice to compact before the 5-hour limit; a keep-warm run stops at once, and **Idle warning** and **Before the cache goes cold** are not used.
  - **Lowest effort** (low, medium or high, default low): how far rightsize lowers.
  - **Highest effort** (high, xhigh or max, default max): never raises above it: not for a prompt, not mid-turn, not for a helper. A model whose rated level is above it gets no route (a review still runs on Opus, at this level at most). A level you are already on above it is left alone.
  - **Lowering** (ask me, lower automatically, never lower or not set, default not set): not set means Ask before changing decides.
  - **Raising** (ask me, raise automatically, never raise or not set, default not set): also decides raises mid-turn when Claude looks stuck.
  - **Stronger model** (ask first, always send, stay, raise effort only, ask each time or not set, default not set): includes the review switch.
  - **Cheaper model** (ask first, always send, stay, lower effort only, ask each time or not set, default not set): a hand-off to a cheaper model.
  - **Remember choices** (ask, every session or this session, default ask): whether rules you set from the band or `/rightsize settings` are kept for later sessions. A rule set in its own row is always kept.
  - **Use Haiku** (on or off, default on): off means no work goes to Haiku, for a hand-off or a Claude subagent. Haiku still rates prompts.
  - **Use Fable** (on or off, default on): off means no work goes to Fable.
  - **Claude's subagents** (cheaper when it fits or off, default cheaper when it fits): whether a general-purpose subagent started without a model runs on the cheapest weaker model that fits.
  - **Workflows** (ask, pause rightsize, follow my rules or right-size every agent, default ask): what rightsize does once Claude starts a workflow. Whichever you pick, measurement stays paused afterward.
  - **Budget pacing** (on or off, default on): on a subscription, moves the fixed hand-off and lowering bars (70% and 90%) by how fast the 5-hour and 7-day windows are used.
  - **Raise when stuck** (on or off, default on): raises effort one level for the rest of a turn when Claude looks stuck.
  - **Rater** (sonnet or haiku, default sonnet): the model that rates each prompt, at low effort. Sonnet reads more reliably; Haiku costs less.
  - **Start suggestions** (weekly, monthly or off, default weekly): the log-based suggestion of another starting model. Off: the report still shows the comparison.
  - **Idle warning** (over $0.10, over $0.50, over $1 or off, default over $0.50): the bar for the band's note on what a cold cache costs. It never holds the prompt.
  - **Before the cache goes cold** (ask, keep warm 2 h, keep warm 8 h, keep warm until my usual start, save a handoff, compact or off): what happens when a big session ends a turn. Not set, rightsize keeps warm until your usual start. Keeping warm never costs more than coming back cold.
  - **Reports** (api or subscription, default api): dollars, or a share of usage. A value you set is final.
  - **Band** (when it acts, always or off, default when it acts): when the band shows.
  - **Question wait** (30 seconds, 1 minute or 2 minutes, default 30 seconds): how long a dialog waits before rightsize takes the choice that changes nothing.
  - **Price check** (monthly or off, default monthly): compare `prices.json` with Anthropic's pricing page every 30 days. `/rightsize prices` checks right away.

Every row in full: [docs/SETTINGS.md](../../docs/SETTINGS.md).

## Turn it off or remove it

- `/mods` pauses it; `/config` turns off single features: **Routing**, **Hand-offs** and **Cache** each switch one off (with Routing and Hand-offs both off, no prompt is rated).
- `claude plugin disable rightsize@archid21` stops it loading and keeps its settings and learning; `claude plugin enable rightsize@archid21` brings it back.
- `claude plugin uninstall rightsize@archid21` removes it and the settings saved in `/config`. Its stored data and logs stay on disk: `rm -r ~/.claude/plugins/store/rightsize_*.json ~/.claude/mods-logs/rightsize*` deletes them.

## What it runs, writes and sends

rightsize is a mod: it runs inside Claude Code and hooks some of its events. This is everything it does outside the chat, and it is the same list the plugin directory's automatic check reports. Each line below was checked against the code (`hooks/register.tsx`). The longer version, with the log fields, is [docs/WHAT-IT-TOUCHES.md](../../docs/WHAT-IT-TOUCHES.md).

- **Programs it runs (`$.process.run`).** Four programs for its logs, no shell, each with a fixed name: `mkdir -m 700 -p` and `chmod` (700 on folders, 600 on files) to make its log folders and files readable by you alone, and `rm -f` and `rmdir` on a session's folder inside `~/.claude/mods-logs/rightsize/` once nothing in it has changed for 45 days (never the current session's, and only a folder whose name is plain letters, digits, `_` and `-`). The only changing part of any command is a path inside those log folders. With whatsnext installed it starts two more, only to compact: `git rev-parse --show-toplevel` (to find your project's folder) and `python3 <whatsnext's folder>/skills/whatsnext/scripts/whatsnext.py` (whatsnext's own script, found in Claude Code's list of installed plugins) with one fixed command: `compact-instructions --session <session ID> --json` (the text to compact with, whether a handoff should come first, and whether this folder is a whatsnext project; it changes nothing). rightsize writes no whatsnext file or setting. It starts no other program and fetches no code.
- **Files it writes (`$.fs.write`).** Three places: the log files under `~/.claude/mods-logs/rightsize/<session ID>/` (see **Logs** below), `prices.json` in its own plugin folder with the old copy kept as `prices.json.bak` (the monthly price check), and its own store in Claude Code's plugin store, `~/.claude/plugins/store/rightsize_*.json` (your answers, calibration, counters). Nothing in your project is written, and none of whatsnext's files is opened by rightsize: whatsnext's script answers instead.
- **Web addresses it contacts (`$.http.fetch`).** One, written out as a fixed https address at its call: `https://platform.claude.com/docs/en/about-claude/pricing.md`, Anthropic's pricing page, a plain GET every 30 days to keep `prices.json` current. It sends nothing of yours. **Price check** set to off stops it. rightsize sends nothing to its author or to any third party, has no analytics or feedback upload, and makes no request while Claude Code's `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set. The rating and the keep-warm request are not web calls of rightsize's own: they go to Anthropic through Claude Code (`$.model`), with your existing sign-in, as your prompts do anyway. The full statement: [docs/PRIVACY.md](../../docs/PRIVACY.md).
- **What it reads.** Your prompt (to rate it: the whole prompt, or its start and end when it is long), the end of Claude's last reply, the session's usage and rate limits, and for each tool call in a turn the tool, its arguments and whether it failed (to spot a stuck turn, a blocked step or a failing test run). From Claude Code's settings it reads `model`, `effortLevel` and its own `pluginConfigs` rows; from the environment it reads the `HOME` variable (to place its logs; `$.env.get`), `CLAUDE_CONFIG_DIR` (where Claude Code keeps its folder) and whether `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is set, and no other variable. With whatsnext installed it also reads Claude Code's list of installed plugins (`installed_plugins.json`) to find whatsnext's folder, and asks whatsnext's script whether your project is one of its own. It reads no credential: no API key, token, keychain or sign-in file, and it never reads the value of `ANTHROPIC_API_KEY` or any other secret. Whether you pay by API or subscription comes from the rate limits Claude Code reports, or from your **Reports** row.
- **Settings it writes (`$.config.set`).** Only its own rows, `rightsize.<row>` for the rows listed under **Commands and settings**, when you answer one of its questions, pick a rule in the band, or run `/rightsize reset`. It never writes the permission mode, another plugin's row or any other setting, and it sets no environment variables.
- **Prompts it submits (`$.prompt.submit`).** One fixed text, `wrap up`, submitted once before a big session's cache goes cold when **Before the cache goes cold** is set to save a handoff and whatsnext is installed and started in the project. When whatsnext wants a handoff before a compaction, the same `wrap up` is submitted once for that. Its other actions use fixed texts through other calls: the keep-warm request is `Reply with the single word OK.` (sent through `$.model.fork`), and the compaction is Claude Code's own `/compact` (`$.session.compact`, or `$.command.run` with whatsnext's instructions when whatsnext is installed and started in the project; from the advice to compact before the 5-hour limit, only when you press its button, with one fixed set of instructions). It never submits text taken from your conversation. Two buttons only put text in the prompt box for you to send yourself: your last prompt again (Retry, Run on your model) and `/model sonnet` (start suggestion).
- **The `tool.call` hook (the permission hook).** It watches each tool call and passes every one on unchanged with `next(e)`. It only ever denies, in four cases inside its own helpers: a step only you can approve (a shell command that pushes, publishes, releases, deploys or merges, or an MCP tool whose action starts with send, publish, deploy, merge or post) when a hand-off subagent tries it; any call of a helper that was stopped and sent back to the main chat; rework past a task's retry budget; and the calls of a helper on a cheaper model past its call cap (25 for Haiku, 40 for Sonnet). It never approves a call and never changes a permission decision anywhere else. Before a workflow starts it can ask you a question on the band, and the call goes on once you answer.
- **Other hooks.** `prompt.submit` rates the prompt, may change the effort level and adds the hidden hand-off note (your text is not changed; in watch only it plans and logs and applies nothing). `turn.start` and `turn.complete` measure the turn; `turn.complete` may start a keep-warm timer. `turn.step` watches for a stuck turn. `agent.spawn` passes the event on with `next(e)` and never denies; it changes only the `model` of a general-purpose subagent that names none, moving it to a cheaper one. `config.set` passes every event on with `next(e)`, never denies, and ignores rows that are not its own; it only watches its own rows. `command.run`, `session.start` and `ui.render` serve its command, start-up and the band. It starts nothing while a turn runs.

## Limits

- The app's effort picker does not move. The status line shows the level in use.
- Helpers keep their own model and effort unless rightsize hands them work, or Claude started them as general-purpose without naming a model.
- The rating is an estimate from a model. Calibration corrects cost guesses, not a wrong choice of model. rightsize measures how often the rating was wrong and stops trusting it where it keeps missing, but only once enough outcomes are in.
- Hand-offs usually take longer than staying, because of the brief and the check. The band says so; the report's Time section compares them.
- This is an independent project, not made or endorsed by Anthropic.

## Logs

Each session writes its own folder, `~/.claude/mods-logs/rightsize/<session ID>/`, and no other session writes to it. `/rightsize report`, the start suggestion and the miss rates read every session's folder together. A folder unchanged for 45 days is removed when a session starts. In each folder:

- `rightsize.log`: each decision.
- `runs.jsonl`: one JSON line per rated turn (the change made and suggested, estimated and actual cost, rating cost, rate-limit windows, duration, subagent calls, each model's rated level, whether it continued its task or corrected the last reply, keep-warm and workflow data), plus `unrated`, `dropped` and `unbound` lines for prompts that never ran, `check` lines for spot-checks, `feedback` lines for each 👍 or 👎, `warm` lines for keep-warm requests and `warmSaved` lines for what they saved. Lines such as `cold` (your answers to keep-warm offers) and `warmSaved` are no part of any report figure.
- `switches.jsonl`: each measured effort switch, and whether the cache was kept.

## Privacy

Logs stay on your machine. rightsize sends nothing to its author or to any third party; its only web request is a monthly fetch of Anthropic's pricing page. The rating call carries your prompt to Anthropic through Claude Code, as your prompts go anyway. What the rating call sees, 👍/👎, how to give feedback and how to delete data: [docs/PRIVACY.md](../../docs/PRIVACY.md).
